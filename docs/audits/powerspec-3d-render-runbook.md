# PowerSpec Runbook: render a generated 3D model on screen

This is the part that cannot run in the cloud container: it needs the RTX 5080 on the PowerSpec (`GrizzieWorkShop`). Everything before the generation step is already covered by tests; this runbook produces the one thing the tests could not, a real model generated by the GPU and shown in the dashboard viewer.

| Field | Value |
|---|---|
| Machine | PowerSpec (RTX 5080, driver 610.88, Docker 29.9.3 on WSL 2) |
| Code | Fresh clone of `repair/p0-recovery-2026-10`. Do not use `D:\BrightForge` or `C:\Users\daley\Projects\BrightForge`; they hold unpushed work |
| Approvals needed | Model downloads (several GB; the project never downloads models by itself) and one GPU generation. Nothing here touches API keys |
| Already shown to work | The viewer renders a GLB fixture (`test/fixtures/cube.glb`) in headless Chromium. The `requirements.txt` header records torch 2.11.0+cu128 verified on an RTX 5080 on 2026-11-05 |

## 1. Fresh clone and Node side (PowerShell)

```powershell
cd "C:\AgentForge Control\work"        # any empty folder you own
git clone --branch repair/p0-recovery-2026-10 https://github.com/GrizzwaldHouse/BrightForge.git brightforge-render
cd brightforge-render
git log -1 --oneline                    # write this hash down
npm ci
npm run lint                            # expect 0 errors
```

## 2. Python environment with the Blackwell (sm_120) PyTorch build

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -m pip install -r python\requirements.txt
.venv\Scripts\python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

Expected: a `+cu128` version, `True`, `NVIDIA GeForce RTX 5080`. If it prints `False`, stop: the dashboard will fall back to CPU, which takes about ten minutes per image and is not a useful test.
`hy3dgen` (Hunyuan3D) is not on PyPI; follow the install note at the top of `python/requirements.txt`.

## 3. Environment check, then models (needs your approval)

```powershell
.venv\Scripts\python python\setup.py --check-only      # no installs, no downloads
.venv\Scripts\python python\setup.py --skip-install     # downloads models into data\models (several GB)
```

Run the second command only after you have decided the disk space and download are acceptable.

## 4. Start the app and generate

```powershell
npm run server                          # http://127.0.0.1:3847, loopback only
```

In the browser:

1. Open `http://127.0.0.1:3847` and select **Forge3D**. The banner "GPU not available" must be gone and **GPU / VRAM** must show the RTX 5080. If not, open `http://127.0.0.1:3847/api/forge3d/bridge` and read the `state` field.
2. Type: `a red medieval sword`, type **Text to 3D (Full Pipeline)**, press **Generate**.
3. Wait for the job to reach `complete`. The model appears in the viewer. Rotate it with the mouse.
4. Take a screenshot (Win+Shift+S) with the model visible. Save it as `docs\audits\evidence\3d-render-<date>.png` in the clone.

Check the file itself (independent of the viewer):

```powershell
.venv\Scripts\python -c "import trimesh,glob; p=sorted(glob.glob('data/output/*/*.glb'))[-1]; m=trimesh.load(p, force='mesh'); print(p, len(m.vertices), 'vertices', len(m.faces), 'faces', 'watertight' if m.is_watertight else 'open')"
```

## 5. What counts as done

| Check | Pass condition |
|---|---|
| GPU path | `torch.cuda.is_available()` is True and the bridge state is `running` |
| Generation | A job finished with status `complete`, not `failed`/`dead_letter` |
| File | A `.glb` exists with more than 100 faces |
| Screen | The screenshot shows the model in the viewer, not an empty canvas |
| Honesty | Note the generation time, VRAM used, and any CPU fallback in `docs\audits\evidence\3d-render-<date>.md` |

## 6. If it fails

Record the exact error from the terminal running `npm run server` and from `sessions\bridge-errors.log`. Do not change code on this machine; send the log back and the fix is made in the repair branch. Known risk: VRAM exhaustion and the Windows GPU timeout (TDR); see `docs/SETUP.md` step 4.
